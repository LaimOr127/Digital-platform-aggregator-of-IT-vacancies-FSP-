# Памятка для жюри

Стенд: **https://201-24-62-88.sslip.io** · документация API:
`https://201-24-62-88.sslip.io/api-docs/`. Все данные на стенде синтетические.

## Как проверить сквозной сценарий

1. **Регистрация кандидата** — `/register`, роль «Я ищу работу». Письмо со ссылкой подтверждения
   реально уходит на указанную почту через SMTP российского почтового сервиса (`make smtp`,
   `docs/integrations.md` → «Настройка SMTP»). Если письмо задержалось — войдите в готовый аккаунт
   без пройденного теста (ниже).
2. **Опрос и тест** — «Профиль → Грейд»: специализация, грейд, стек → 15 заданий → категория.
   Не сдали — сразу доступен тест на грейд ниже; этот грейд и выше — через 14 дней (так же после
   брошенного теста и в другой специализации).
3. **Работодатель** — войдите в демо-компанию: «Каталог кандидатов» → категория → «Пригласить» с вилкой.
4. **Кандидат** видит приглашение в «Поиск работы → Приглашения», принимает — компания видит контакты.
5. **Отклик на вакансию** — «Поиск работы → Вакансии» → «Откликнуться».

## Демо-аккаунты

Пароль один для всех. В репозитории его нет: команда задаёт пароль при заливке стенда и передаёт
жюри отдельно — вместе со ссылкой на стенд.

| Аккаунт | Что внутри |
|---|---|
| `demo-new-1@example.org`, `demo-new-2@example.org`, `demo-new-3@example.org` | новые кандидаты: опрос и тест не пройдены — пройдите их сами |
| `demo-candidate@example.org` | кандидат с заполненным профилем, категорией и достижениями |
| `demo-hr@example.org` | компания с описанием, вакансиями (часть пора продлить, есть черновик) и задачами для кандидатов |
| `demo-hr-pending@example.org` | компания на модерации: вакансии — черновики, каталог закрыт до одобрения |
| `demo-hr-blocked@example.org` | заблокированная компания: вакансии сняты модератором |
| `demo-blocked@example.org` | заблокированный кандидат — вход отклоняется, так работает блокировка |

Каталог, лента вакансий и радар зарплат заполнены синтетическими кандидатами и компаниями — новый
пользователь сразу видит непустые разделы.

## Привязка ФСП

«Профиль → ФСП» → ID участника `FSP-24001` … `FSP-24007` → код подтверждения. **Это режим
демо-стенда** (`FSP_DEMO_CODES_PROD=true`): реальных писем ФСП нет, поэтому код показан прямо в
интерфейсе с пометкой «Демо-стенд». В рабочей системе код приходит только по каналу ФСП — на почту
аккаунта ФСП, интерфейс его не видит. После привязки — достижения, уровень ФСП и паспорт навыков.

## Для команды: подготовка стенда

```bash
make env                                   # затем в .env: SITE_ADDRESS, PUBLIC_URL, SMTP_*, FSP_DEMO_CODES_PROD=true
make prod
make create-admin EMAIL=admin@ваш-домен
make smtp MODE=prod                        # почта: спросит ящик и пароль приложения, проверит вход
read -rs DEMO_PASSWORD && export DEMO_PASSWORD   # пароль демо-входов: не в истории команд и не в логах
make seed-demo MODE=prod STAND=1 N=2000 C=8
```

Повторный `make seed-demo` добавляет кандидатов, но существующие демо-аккаунты и их пароль не меняет.
Пароли и ключи живут только в `.env` на сервере (права 600, в git не попадает); `make secrets-check`
проверяет историю репозитория gitleaks'ом.
