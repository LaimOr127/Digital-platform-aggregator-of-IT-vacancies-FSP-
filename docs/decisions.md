# Решения: почему сделано так

Каждое решение — что выбрали, почему и чем за это платим. Если решение меняется, обновите запись,
а не просто код: следующему разработчику важно знать, от чего уже отказались и почему.

## Архитектура

**Монолит API + worker на одном коде, а не микросервисы.** Команда из трёх человек и сервер на 1–2 ГБ.
Один образ, общий доменный код, одна транзакционная граница. Масштабирование — процессы и реплики api
(лимиты и блокировки уже общие через PostgreSQL). Цена: при росте отдельные части (подбор) придётся
выносить или предрасчитывать в worker.

**PostgreSQL вместо Redis, брокера и поискового движка.** Лимиты — `UNLOGGED`-таблица с атомарным upsert,
очередь писем — outbox с `FOR UPDATE SKIP LOCKED`, синхронизация ФСП — аренда пачек. Меньше сервисов —
меньше памяти и точек отказа. Цена: ~3,6 тыс. проверок лимита в секунду — потолок, после которого
понадобится Redis (замена реализации `Limiter`).

**Слои api → services → repositories → models и единая AccessPolicy.** Права в одном месте: правило
меняется в одной строке, тест IDOR перебирает все маршруты автоматически. Роутер не принимает решений.

**RLS как вторая линия.** Репозиторий фильтрует по владельцу, но ошибка в одном запросе не должна
открыть чужие профили. PostgreSQL проверяет то же самое по контексту `app.user_id`/`app.role`.
Цена: каждый новый запрос к защищённой таблице должен идти в правильном контексте; агрегаты для всех
(радар зарплат) читаются в `system_scope` и отдают только числа с порогом k-анонимности.

**Две роли БД.** Приложение не может менять схему и удалять аудит даже при SQL-инъекции; миграции —
отдельной ролью в one-shot контейнере.

**Outbox для писем.** Письмо ставится в очередь в той же транзакции, что и действие: нет писем о том,
что не произошло, и ответ API не ждёт SMTP. Параметры писем зашифрованы и стираются после отправки.

## Безопасность и приватность

**Access-токен в памяти, refresh — в httpOnly-cookie с CSRF.** XSS не унесёт долгоживущий токен,
CSRF не обновит сессию без заголовка. Refresh одноразовый, повтор отзывает цепочку (признак кражи).
Цена: обновление страницы делает запрос refresh; параллельные вкладки синхронизируются через Web Locks.

**Регистрация не выдаёт занятые адреса.** Всегда «проверьте почту», хеш пароля считается и для занятого
адреса (одинаковое время ответа), владельцу уходит письмо. Цена: пользователь узнаёт о дубле из письма,
а не из формы.

**2FA администраторов с кодом подключения из CLI.** Пароль администратора не даёт привязать свой
аутентификатор — нужен одноразовый код, который оператор сервера передаёт лично.

**Неверный пароль при подтверждении действия — 403 `wrong_password`, а не 401.** 401 клиент понимает как
«истёк токен» и обновляет сессию; здесь сессия жива.

**Подтверждение почты оператором (`make confirm-email`), а не флаг «без подтверждения».** Флаг легко
забыть включённым в prod — тогда любой зарегистрируется на чужой адрес. Команда требует доступа
к серверу, адресна и пишется в аудит.

**Шифрование имени и контактов с привязкой к полю и владельцу.** Утечка дампа не раскрывает
персональные данные; шифртекст нельзя переставить в чужую строку. Цена: поиск по имени невозможен
(он и не нужен — кандидат анонимен), смена ключа требует перешифровки.

**Анонимность до принятия оффера.** `anon_id` не связан с id пользователя, в каталоге нет имени,
контактов, ID ФСП и названий соревнований. Контакты — снимок на момент принятия, каждый просмотр
записывается.

**k-анонимность в аналитике.** Группа от 5 значений, данные компаний — от 3 компаний, округление до
тысячи: по медиане нельзя восстановить вилку одной компании или зарплату одного человека.

**ИИ — необязательно, с согласия и без контактов.** Любая модель за интерфейсом, ответ проверяется
схемой, при ошибке работает алгоритм. Адрес модели проверяется по фактическому IP (защита от SSRF
через DNS и десятичные IP).

## Продукт

**Категория — по тесту, а не по резюме и не по ФСП.** ТЗ требует категорию «специализация × грейд»,
определяемую опросом и тестом; достижения ФСП — усиление внутри категории. Первая версия строила
категории по дисциплинам ФСП — это оставлено как дополнительный фильтр.

**Тест — банк параметрических шаблонов и IRT, а не нейросеть и не единый набор.** Единый набор
распространяется, задания от нейросети несравнимы по сложности. Шаблон фиксирует сложность, генерация
даёт уникальные варианты, модель 3PL сравнивает кандидатов на одной шкале ([assessment.md](assessment.md)).
Цена — ручная работа над банком; оценка показала, где его расширять.

**Подбор — взвешенные факторы, а не ML.** Работодателю показывается вклад каждого фактора
(«Почему 82 %»). Без GPU и обучающих данных; новый фактор — новый класс. Веса под вакансию: категория 30,
тест 20, навыки 20, ФСП 10, описание, актуальность, формат, зарплата — по 5. Фактор теста под вакансию —
близость уровня к её грейду: так показала процедура оценки ([validation.md](validation.md)).

**Выход на контакт — приглашение без обязательной вакансии.** Смысловой центр ТЗ: работодатель сам
приходит к кандидату с описанием и вилкой; отклик на вакансию — дополнительный сценарий. Контакты — после
согласия кандидата, статус «просмотрено» видят обе стороны.

**Компании без премодерации.** ТЗ выносит верификацию работодателей за рамки MVP: компания после
регистрации сразу работает, модерация — постфактум; премодерация включается `COMPANY_PREMODERATION=true`.

**Собеседование перед оффером.** Оффер без встречи — нереалистичный сценарий; оффер только по итогу
`passed`, один на собеседование. Кандидат выбирает слот из предложенных — без переписки.

**Вакансия живёт 14 дней.** Компания подтверждает актуальность или закрывает вакансию; истёкшие
не видны на уровне БД.

**Вилка обязательна** в вакансии и оффере — главный принцип «честного найма» из плана.

**Паспорт навыков подписан Ed25519.** Работодатель на любой площадке проверяет подлинность сам по
публичному ключу, не доверяя нашему серверу. Отзыв согласия — отзыв паспорта.

## Инфраструктура и разработка

**Compose-файл на каждый сервис.** Поднимается любая комбинация (`make up S="db api"`), общие настройки
безопасности (non-root, read-only, `cap_drop`) — один раз в `deploy/common.yml`.

**Мок ФСП с тем же контрактом.** Реального API нет; мок позволяет разрабатывать и демонстрировать,
а замена — одна переменная `FSP_BASE_URL`.

**Тесты на SQLite и на PostgreSQL.** SQLite — быстрый прогон логики, PostgreSQL — RLS, роли,
`SKIP LOCKED`, лимиты. Оба в CI.

**График без библиотеки.** Нужен один тип (диапазоны), библиотека добавила бы сотни КБ.

**Типы фронта из OpenAPI.** Контракт один; расхождение ловит `tsc`.
